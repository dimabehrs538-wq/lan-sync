# 共享者（v0.3.1 起）

只有**共享者**可以切换文件夹的共享模式（协作 / 只读共享）。共享者记录在每台电脑自己的内核设置
（`settings.json` 的 `owners`）中，一旦确定就不会改变，也**不会**从随文件夹同步的 `.teamsync.json` 推导。

## 如何确定

| 情况 | 共享者 |
|---|---|
| 在本机新建文件夹 | 本机 |
| 接受邀请 | 发出你所接受的那条邀请的设备 |
| 本机移除文件夹后重新接受 | 重新按邀请记录 |

## 成员何时跟随 `.teamsync.json`

成员的内核只有在以下条件**全部**满足时才切换本机文件夹类型（只读 ⇄ 协作）：

1. 文件中的 `owner` 等于本机记录的共享者；
2. 引擎数据库（`/rest/db/file`）中该文件的**全局版本和本机版本**都由共享者设备最后修改（`modifiedBy` = 共享者短 ID）；
3. 磁盘上的文件与数据库记录一致（大小、修改时间），即没有尚未扫描的本机改动。

否则忽略该文件，并在内核日志中记录原因（同一文件夹同一原因只记一次）。
成员手工编辑或伪造的 `.teamsync.json` 即使同步到其他成员，也会因为最后修改者不是共享者而被忽略。

## 旧版本升级（迁移规则）

升级后，对还没有共享者记录的文件夹按顺序取第一个成立的规则，只执行一次：

1. 本机为“仅发送”（只读共享的共享者）→ 本机；
2. 协作文件夹且本机有 TeamSync 新建文件夹时写入的 `.stignore`（接受邀请时不会写入，`.stignore` 也不会同步）→ 本机；
3. 存在可信的 `.teamsync.json`（全局与本机版本都由文件中 `owner` 设备修改，且该设备是文件夹成员），且 `owner` 不是本机 → 该设备（自称本机为共享者的文件不采信）；
4. 文件夹中除本机外只有一台设备（接受邀请时只加入了邀请人）→ 该设备；
5. 否则记为**未知**：谁都不能切换模式，成员也不跟随任何模式文件。

共享者未知时，可在“共享设置”中由用户在本机手动指定一次（CLI：`teamsyncd set-owner <文件夹ID> <设备ID>`）。
这只影响本机的判断；其他成员仍按各自的记录判断，所以无法借此控制别人。

已知局限：如果在 v0.3.0 及更早版本中，某个成员曾抢先切换过模式（写入了自称共享者的 `.teamsync.json`），
规则 3 在第三方成员处可能把该成员认作共享者。此时可在该成员处移除文件夹后由真正的共享者重新邀请。
